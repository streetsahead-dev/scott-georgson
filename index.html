How I work with AI

AI writes most of the code and the first drafts. The technical judgment is mine: what to build, how it should be structured, where AI belongs, and whether the result holds up with real users.

Choose the tool

Plain rules where a grade or a flag must be explained

The reading-grade console is spreadsheet formulas and Apps Script with no AI in the loop, so every score can be walked through with a parent. AI answer features are stripped from student search. AI goes where it helps: drafting, evaluation, building.

Set the rules first

Policy, training and a test for every tool

I wrote the school's AI-use policy and parent guide and trained the staff. Any tool I recommend has to save a teacher real time without requiring students to use AI. I chose Flint as the student platform and rolled it out.

Document the pipeline

A repeatable production line, not one-off prompts

FastForwardED resources come out of fixed instructions: intake questions before any build, a house style spec, a compliance check after, and a catalog registry that flags overlap with earlier products. I vet each one before it is listed.

Decide, then test

Architecture calls are mine, and classrooms test them

Authentext pairs statistical scoring with a Claude evaluation layer, and I decided how the two divide the work. Voice Grader ran in my own classroom before any colleague saw it, and the reading console runs every week with a real teacher.

FastForwardED production line

  1. Intake questions
  2. Build to house spec
  3. Compliance check
  4. Overlap check against catalog
  5. My vetting
  6. Listed

For product suites, several evaluators review the candidate ideas before anything is built, and a weak or overlapping idea gets cut at that stage.

Systems at St. Paul's Lutheran, PreK–8

Reading accountability console

Google Sheets, Apps Script

In use
Problem
When the school went 1:1, Accelerated Reader quizzes could be taken unproctored, and the ELA policy needed weekly scoring for about 75 students in grades 6–8.
Built
A console that scores each student from a weekly report paste against the written policy: goal completion, quiz accuracy and habits. The teacher's only input is a weekly infraction tally. A three-tier progress chart shows who is behind, and policy values sit in a config tab so a rule change needs no code.
Standing
Running weekly. Scoring is plain rules, so a grade can be explained line by line.

Student start page and games launcher

GitHub Pages, Google Sheets, Chrome policy

Live
Problem
Students needed one place to reach approved tools. Classroom pages at small schools tend to be dead by year three because nobody keeps them up.

A static page that reads its links and game list from a published spreadsheet, so teachers edit a sheet, not code. Chrome policy sets it as the new-tab page on student Chromebooks. A hidden bonus board switches on for special occasions, and click tracking is aggregate only.
Standing
Live on student Chromebooks.

Independent products, Streets Ahead LLC

Authentext

Web platform for teachers

Beta-ready
Problem
Teachers have no good way to tell whether a draft sounds like the student who handed it in.
Built
A platform that profiles each student's own writing with stylometry (character n-grams, function words, part-of-speech patterns and structural features), compares new work to that baseline, and adds a Claude evaluation layer. It has tiered scoring with genre stratification, a teacher dashboard, Google Classroom roster and work import, onboarding, and a writing diagnostic. I am now building a growth baseline that coaches a student's voice as well as checking it.
Standing
Built and beta-ready. I am recruiting its first teacher testers.
